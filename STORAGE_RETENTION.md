# Хранение текущей серии

Новая отдельная серия R4/R5: `runs/research/common_pool_v1/`, шесть конфигураций с Qwen encoder и восемью дополнительными FFN-экспертами на MoE-слой. На этапах A1/SFT1/SFT2/DET сохраняется один model-only final checkpoint с best/last ссылками. Веса потреблённого этапа можно удалить только после passed независимого native proof преемника, сверки initialization SHA, ownership/границ путей и отсутствия fd/mmap. Финальные DET-веса всех шести вариантов сохраняются. Никакие веса прежней серии из 18 вариантов или файлы `exports/paper_v1` не удаляются новой очередью: пользователь скачивает их. Наименьший резерв — 32 ГиБ сверх следующего checkpoint. Протокол R4/R5 описан в конце `RESEARCH_PIPELINE.md`.

На 26 ноября финальная серия `runs/research/detection_mix_v1` завершена: 18 из 18 конфигураций с независимыми native proofs. Для неё сохраняется один физический финальный checkpoint на вариант; best/last указывают на него. Правила предыдущих этапов ниже оставлены для истории. Компактная локальная выгрузка описана в конце файла; подготовка архива не удаляет финальные веса на сервере.

Уточнения пользователя: удалять устаревшие ненужные веса, держать best/last, резервировать место под checkpoint. Подтверждение для разрешённой очистки не требуется. Текущие SFT — `runs/research/fixed_capacity_eval_v5`, обязательные A1 — `runs/research/fixed_capacity_v4`, четыре фиксированных блока, не более двух SFT-проходов.

Сохраняются:

- B4 checkpoint после P1/P2: максимум два физических SFT объекта на конфигурацию. На каждом этапе best/last — ссылки на один финальный объект. Между проходами aggregate best/last выбирается в `research_results/capacity_eval_v5/best_last_by_arm.json`; P1 нужен также для сравнения длительности.
- Завершённые B2 результаты в `runs/research/additive_visual_v1` для сравнения ёмкости. SmallThinker/Qwen/R1 P1 дополнительно является источником B2 continuation; его удалять нельзя.
- Шесть full-finetune R2-контролей и необходимые незавершённому R2 alignment checkpoints.
- Шесть маленьких caption-P артефактов `runs/research/additive_visual_v1/projectors/`. Их большие прежние источники уже удалены после потребления старыми12 A1; новая серия читает P-артефакты напрямую с проверкой hashes/refs.
- Frozen исходные LLM, vision encoder/merger, используемые датасеты и общий BF16 feature cache.
- Компактные metrics/configs/protocols, source snapshots и receipts удаления.

Новый B4 A1 удаляется только после passed независимого GPU reload/replay SFT/P1. SFT/P2 инициализируется P1, а не A1. Final delta checkpoints содержат LoRA/блоки/gates/P, без копии frozen base и без Adam states. P2 запускает новый AdamW, поэтому optimizer resume не заявляется. Epoch/update checkpoints сверх best/last не создаются.

Перед сохранениями и этапами проверяется минимум32GiB свободного места сверх staging. Удвоение проходов не удваивает downloads/cache. При нехватке места сначала удаляются разрешённые obsolete/A1 объекты; действующие зависимости и лучшие/последние веса сохраняются.

Перед удалением проверяются ownership, границы путей, hashes, зависимости, открытые mmap/files. GPU-worker не останавливается; краткая lease при необходимости касается только CPU admission. Каталог `datasets/research/pilot-v1/images` содержит используемые training images и не удаляется по историческому имени.

Уже удалены:28 старых pilot/smoke/common-pool checkpoint,113.708GiB; routed-веса новой отменённой ветви,5.2648GiB; шесть потреблённых больших источников проекторов,10.94555GiB. Compact routed metrics: `research_results/fixed_only_v2/archived_routed_metrics.json`. Журналы и планы: `research_results/storage_retirement_v1/`. Незапущенные старые B2 A1 после перехода не нужны B4; их возможная очистка требует той же проверки открытых файлов и зависимостей.

Операционные инструменты: `scripts/retire_superseded_research_v1.py`, `scripts/watch_research_storage_retention_v1.py`; штатное удаление новых A1 реализовано контроллером v4. Завершённый старый watcher потреблённых источников повторно запускать для B4 не требуется. Предыдущая политика сохранена в `research_results/capacity_v4/previous_STORAGE_RETENTION.md`.

После естественного перехода на B4 удалены ещё четыре неиспользуемых B2 Giga A1, **2.53165GiB**. Проверены отсутствие зависимостей активного плана, ownership и открытые fd/mmap; GPU-worker сигналов не получал. Журнал: `research_results/capacity_v4/obsolete_A1_retirement/completed.json`. Завершённые B2 SFT и источник B2 continuation сохранены.

V5 дополнительно сохраняет одну временную `recovery/model.pt` после последнего optimizer update и до evaluation. Она не содержит optimizer. Если evaluation падает, используется только оценка сохранённых весов. Recovery удаляется после passed final GPU replay, одновременно с потреблённым A1 после P1. Нельзя удалять root v4 целиком: там находятся все12 действующих B4 A1, ещё нужных SFT v5. Неудачные v4 SFT не имеют завершённых обученных checkpoint; их error/metrics history сохраняется для аудита33 неудачных попыток. Суммарно best/last политика по двум завершённым проходам не меняется.

После нового финального SFT с detection (`DETECTION_PIPELINE.md`) потреблённые старые full-train R2 веса могут удаляться только после независимого proof нового checkpoint, проверки исходного SHA и отсутствия fd/mmap. Предыдущие metrics/predictions/configs остаются. Старый controller autostart отключается после естественного завершения, новая очередь использует общий GPU admission lock. Pending last сохраняется до evaluation, scored best/last используют один физический файл через hardlink. Резерв на следующий checkpoint проверяется перед обучением, не только при сохранении.

Для копирования на свой компьютер используется `sync.sh` с обязательным каталогом назначения. Пакеты находятся в `exports/paper_v1/`. Уточнение пользователя: нужны результаты **каждого** обученного варианта; отбор трёх лучших не подходит. Избыточная выгрузка трёх весов удалена, исходные 18 финальных checkpoint сохранены.

Чтобы пересчитать метрики всех 18 вариантов по уже полученным ответам, достаточно около **9 МиБ** метрик, raw predictions, эталонов и конфигураций:

```bash
scp -P 23303 -i ~/.ssh/yacloud root@162.43.170.108:/workspace/gigachat_vl/sync.sh ./sync.sh
bash ./sync.sh --metrics-only ./paper_metrics

# Из локальной Git-копии проекта: стандартный Python, без Torch, GPU и HF downloads.
python3 scripts/recompute_paper_metrics_v1.py --bundle /путь/к/paper_metrics
```

Пересчёт независимо применяет действующие VQA/ANLS/chart/MCQ и detection scorers к исходным ответам и эталонам. Сохранённые per-record score не используются. Проверяются уникальность и полнота ID, 116 VQA и по 64 detection validation/test примера, совпадение групповых метрик и знаменателей. Итоговые `comparison.csv` и `metrics.json` записываются в `paper_metrics/recomputed_metrics/`. Проверено: все 18 финальных строк совпадают с исходными результатами. Это пересчёт ответов, а не повторная генерация моделью.

Для повторного запуска **каждой из 18 моделей** дополнительно нужны их финальные веса. Их скачивает режим по умолчанию (или явный `--all-final`):

```bash
bash ./sync.sh ./paper_all_final
# Эквивалентно: bash ./sync.sh --all-final ./paper_all_final
```

Состав полной финальной выгрузки:

- Ровно один физический финальный checkpoint для каждой из 18 конфигураций; best/last — ссылки на него.
- Метрики, ответы, конфигурации, native reload proofs всех 18 финальных вариантов; компактные отчёты предыдущего этапа и исходного Qwen2.5-VL INT4.
- Эталоны оценки; 167 уникальных оценочных изображений и их исходные cached BF16 features для двух энкодеров в `evaluation_assets.tar.zst`.
- Протоколы и pinned repo/revision базовых моделей. Код переносится через Git.

Промежуточные веса, optimizer states, полные обучающие датасеты, полный feature cache и HF model cache не скачиваются. QLoRA-чекпоинты требуют соответствующую frozen базовую LLM, указанную в конфигурации. Before-stage метрики сохранены для сравнения; прежние потреблённые R2 веса ранее удалены по протоколу и в эти пакеты не входят.

Почему веса всё ещё велики: шесть независимых full-train R2 checkpoint в исходном FP32 занимают **172.83 ГиБ**, остальные 12 LoRA/visual-block checkpoint — **11.37 ГиБ**. Все финальные веса вместе — **184.20 ГиБ**. С оценочными assets и metadata полная выгрузка занимает **184.79 ГиБ** локально вместо примерно 225 ГиБ прежней полной копии. Это финальные веса разных конфигураций, а не копии эпох. Сокращать их число значит терять возможность заново запускать некоторые варианты.

Сжатие `rsync -z` включено для передачи. Оно без потерь, локальные checkpoint сохраняются в исходном формате. На образцах трёх целых checkpoint zstd level3 уменьшил размер примерно на 7–8%; это ориентир для сжимаемости, не гарантия объёма трафика rsync. Повторное квантование или FP32→BF16 не применяется, поскольку оно может менять предсказания. Существующие архивы оценочных assets сжаты zstd и проверены потоковой распаковкой и SHA256 каждого файла.

На сервере полная выгрузка использует hardlinks к исходным финальным весам, не создавая вторую 184-ГиБ копию. В `manifest.json` сохранены исходные SHA256 checkpoint из независимых native GPU proofs и фактический объём. `reports/weight_coverage.json` явно отмечает, для каких строк включены веса: в `all-final` для всех 18, в `metrics` ни для одной.

Если нужна повторная генерация, распакуйте только оценочные assets из корня полной копии (нужны `zstd` и `tar`):

```bash
zstd -dc evaluation_assets.tar.zst | tar -xf -
```

Для пересчёта готовых ответов распаковка assets не нужна. Абсолютные пути внутри исторических JSON не переписаны; при повторной генерации необходимо настроить пути загрузчика к локальным моделям и assets. Источники scorer берутся из Git без изменения научных формул и фиксированных планов.

Повтор синхронизации пропускает файлы с совпадающими размером и временем изменения. Недокачанные части сохраняются в `.rsync-partial` рядом с целевым файлом; `--no-whole-file` позволяет rsync использовать их как основу и передать недостающие блоки с проверкой целостности. Сохранённые части не следует удалять между запусками. Hardlinks и best/last symlinks сохраняются.

При сетевом сбое скрипт автоматически повторяет передачу: максимум 5 попыток с паузой 10 секунд. Таймаут без обмена данными — 120 секунд. Параметры задаются через `SYNC_MAX_ATTEMPTS`, `SYNC_RETRY_DELAY`, `SYNC_IO_TIMEOUT`. Ошибки диска/прав и явное прерывание не запускают цикл повторов. После Ctrl+C или исчерпания попыток повторите **ту же команду с тем же каталогом назначения**, например:

```bash
bash ./sync.sh --metrics-only ./paper_metrics
# Для весов: bash ./sync.sh ./paper_all_final
```

В начале запуска `sync.sh` создаёт отдельный временный `ssh-agent` и вызывает `ssh-add` для указанного ключа. Пароль вводится один раз через штатный prompt OpenSSH; сам скрипт не читает и не сохраняет его в файлах, shell variables или environment. Разблокированный ключ хранится агентом в памяти до завершения этого запуска. Последующие SSH/rsync подключения используют его через явно заданный `IdentityAgent` и `BatchMode=yes`, включая повторы после сетевого сбоя. При выходе, ошибке или Ctrl+C скрипт завершает только своего дочернего агента и удаляет его временный socket. Существующий пользовательский агент и keychain не изменяются. После нового запуска скрипта пароль вводится снова; нешифрованный ключ не требует пароля.

Нужны стандартные `ssh-agent`, `ssh-add`, `mktemp` в дополнение к bash/ssh/rsync. Это локальное изменение; на сервер не передаются ни пароль, ни приватный ключ. Проверены единственный unlock за запуск с зашифрованным временным ключом, повтор после обрыва, очистка агента после ошибки и сохранение внешнего агента.

Проверено реальным rsync через локальный SSH-стенд: повторная синхронизация передаёт ноль содержимого готовых файлов; ранее скачанные 4 МиБ используются при продолжении 8-МиБ файла; соединение, оборванное посреди файла, восстанавливается автоматически с использованием полученной части. Исходные байты совпадают после докачки. Проверены предел повторов и отсутствие повторов для несетевых ошибок.

Незавершённые серверные `*.partial`/`*.tmp`, секреты и служебные caches исключены. Локальные файлы не удаляются. Новый каталог имеет смысл при переходе с прежней полной копии, чтобы не сохранять лишние старые 200+ ГиБ; для продолжения текущей загрузки нужен именно **прежний** каталог. Предпросмотр без передачи: `bash ./sync.sh --dry-run ./paper_all_final` (пакет уже подготовлен).
